## חיבור הכול — מה צריך לקרות לפני שזה רץ בפרודקשן

### א. הרצת מיגרציות
ארבע־עשרה מיגרציות חדשות (0017–0030). הן רצות דרך `node src/applyMigrations.js` עם ledger ו־checksum, כל אחת בטרנזקציה.

**סדר קריטי:** 0017 מחליף את `business_products` ו־`scraped_products` בטבלה אחת עם views. אם משהו חיצוני כותב ישירות לטבלאות האלה — צריך לבדוק אותו לפני.

**נקודת אל־חזור:** 0017 משנה שם לטבלאות המקוריות (`_legacy`) ולא מוחק אותן. גיבוי לפני, כרגיל.

### ב. משתני סביבה
אין חדשים. `@e965/xlsx` נוסף ל־`server/package.json` — צריך `npm install` בשרת.
כתובת ה־webhook של n8n נשמרת בבסיס הנתונים דרך המסך, לא כמשתנה סביבה — כדי שאפשר יהיה
להוסיף יעד נוסף בלי פריסה.

### ג. מה נדלק אוטומטית
שני workers מתחילים עם השרת: תור העבודות ואוטובוס האירועים. אין תהליך נוסף להריץ.

### ד. בדיקות שכדאי להריץ אחרי הפריסה
```bash
# בדיקות סכימה מול DB אמיתי (על עותק, לא על פרודקשן)
TEST_DATABASE_URL="postgresql://..." npm test
```

### ה. חיבור n8n — מה לעשות בפועל
1. ב־n8n: Workflow חדש → צומת **Webhook**, מתודה `POST`. להעתיק את ה־Production URL.
2. באדמין: **הגדרות מערכת → חיבור n8n → הוספת יעד**. להדביק את הכתובת, לבחור אירועים
   (`order.*` לדוגמה), ולהגדיר סוד.
3. ללחוץ **בדיקת חיבור** — n8n אמור לקבל אירוע `system.test`.
4. ב־n8n אפשר לוודא שההודעה באמת מאיתנו: ה־header `x-mipo-signature` הוא
   `sha256=HMAC-SHA256(secret, "<x-mipo-timestamp>.<גוף הבקשה>")`.
5. `x-mipo-idempotency-key` נשאר זהה בין ניסיונות חוזרים — ה־workflow צריך להתעלם ממפתח
   שכבר טופל.

### שאילתת הכפילות
```sql
select lower(btrim(sku)) as sku_normalized,
       count(*) as products,
       string_agg(id::text, ', ') as product_ids
from public.products
where sku is not null and btrim(sku) <> '' and deleted_at is null
group by 1
having count(*) > 1
order by 2 desc;
```

## ממצאים עסקיים מהנתונים

לא באגים — דברים שהמנוע חשף על הקטלוג עצמו, וכדאי שתחליט לגביהם:

1. **מוצר אחד נמכר מתחת לעלות.** `horp25102` — "סוסים חלטה פרימיום רפאל פטס" — מחיר ₪110, עלות ₪277.91. הפסד של כ־₪168 בכל מכירה.
2. **המרווח החציוני בקטלוג הוא 70.8%**, לא 45%. ברירת המחדל של מנוע התמחור נקבעה ל־70% על סמך זה. טיוטה מוקדמת עם 45% הייתה מציעה להוריד 120 מתוך 123 המוצרים המתומחרים בממוצע של 43%.
3. **121 מוצרים בלי מחיר קיבלו הצעת מחיר** מהעלות. הם ממתינים לאישור ולא יתפרסמו עד אז.

## באגים שנתפסו תוך כדי בנייה

מתועדים כאן כי כל אחד מהם היה מגיע לפרודקשן:

1. **מוצרים לא־מבוקרים היו גלויים בחנות** — ה־view סינן מה להסתיר במקום מה להראות, ולכן 267 מוצרים ממתינים הופיעו למכירה. תוקן ב־0023.
2. **אי אפשר היה לקנות מוצר מגורד** — ה־view לא חשף `stock_status` שהקופה שולפת. תוקן ב־0020.
3. **מוצר חדש שני נעלם מרשימת השינויים** — האינדקס הייחודי מיזג מוצרים שאין להם עדיין מזהה. תוקן ב־0025.
4. **מספרי שורות הצביעו לשורה הלא נכונה** בקובץ — האינדקס נלקח מרשת שכבר נוקו ממנה שורות ריקות.
5. **תיקון נתיבי התמונות בלע מילה מהנתיב** לתוך שם הקובץ.
6. **`attempts` בפונקציית התפיסה של האוטובוס היה דו־משמעי** — Postgres פתר אותו מול פרמטר
   הפלט של הפונקציה ולא מול העמודה, וכל שליחה נכשלה. נתפס בבדיקה מול DB אמיתי.
