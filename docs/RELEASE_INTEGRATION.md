# פריסת `claude/integration`

הענף מאחד 18 יחידות עבודה שהצטברו מאז הפריסה האחרונה. הוא נבדק, והמסמך הזה
הוא מה שנשאר לעשות.

## מה נכלל

תשתית: גיבוי DB לפני מיגרציות · סביבת staging (קוד בלבד) · CI מול DB אמיתי
· outbox טרנזקציוני · מזהה חיצוני לכל ישות · שכבת AI עם ספר עלויות.

לקוחות: מסך לקוחות באדמין · זהות לקוח מאוחדת · הערות ושיחות · אימות מייל ·
אישור תנאים בהרשמה · ניהול חיות מחמד · אוואטר ומצבי רוח.

חנות: תווית מחסן מלאה (מק״ט, משקל, ברקוד, שליחה בוואטסאפ) · פרופיל משלוח מלא
· עץ קטגוריות · דף מוצר כתבנית · בעלות על תמונות המוצר.

מותג: הלוגו האמיתי ושינוי `petid` ל-`mipo` בכל המערכת.

**לא נכלל:** `claude/admin-2fa`. הוא דורש `SECRET_ENCRYPTION_KEY`, ובלעדיו
ה-API מסרב לעלות בפרודקשן. ראו `docs/ADMIN_2FA_DEPLOYMENT.md`.

## מה נבדק

| | |
|---|---|
| lint · typecheck · build | נקיים |
| בדיקות שרת | 104 עוברות |
| 31 מיגרציות על DB ריק | כולן |
| **שדרוג מ-0016 עם נתונים** | 15 מיגרציות, שום שורה לא אבדה |
| דליפת מחיר עלות | אפס — ציבור 36 שדות, אדמין 55 |
| מסע מלא | הרשמה · כניסה · חנות · הזמנה · אדמין |

מיגרציה `0019` מוחקת `email, full_name, phone, birthdate` מ-`profiles`. נבדקו
שלושה מצבים: נתונים תואמים (ללא שינוי), נתונים שקיימים רק ב-`profiles`
(הועברו ל-`app_users` לפני המחיקה), ונתונים סותרים (`app_users` מנצח, עם
אזהרה בלוג). **הפעולה בלתי הפיכה.**

## שני שינויים שהמשתמש ירגיש

**1. לקוח רשום שלא אימת מייל לא יוכל להזמין.** `email_verified_at` נוסף כ-NULL
לכל החשבונות הקיימים, ואין backfill — זו החלטה מכוונת. רכישת אורח לא נפגעת.
הלקוח רואה באנר, מבקש קוד ומאמת; המסלול נבדק מקצה לקצה.

**2. אין.** דף שנטען לפני הפריסה היה נשבר בתשלום, כי `building` הפך לחובה.
נוסף מסלול תאימות: בקשה שאינה נושאת אף אחד מהשדות החדשים מטופלת לפי הכללים
הישנים. הטופס החדש עדיין נדרש לכל הכללים.

## הצעדים

### 1. גיבוי — מומלץ, כבר לא חוסם

`0018_snapshot_profile_identity.sql` רץ מיד לפני `0019` ומעתיק את ארבע
העמודות ל-`profiles_identity_snapshot` לפני שהן נמחקות, כך שהמחיקה ניתנת
לשחזור בלי גיבוי ידני.

גיבוי מלא עדיין מומלץ, כי הוא מכסה גם מה שאינו קשור למיגרציה הזו:

```
ssh -i ~/.ssh/mipo-prod-key.pem ubuntu@63.183.241.110
cd /opt/mipo && bash deploy/aws/backup-before-migrate.sh
```

מהפריסה הבאה ואילך הוא ירוץ אוטומטית, כי `deploy-backup` נכלל בשחרור הזה.

### 2. המיזוג — הוא הפריסה

```
git fetch origin
git checkout aws-migration && git pull
git merge --no-ff origin/claude/integration
git push origin aws-migration
```

הדחיפה מפעילה את `Deploy AWS`: build, מיגרציות, restart, smoke test.

### 3. אחרי

- לוודא ש-`https://mipo.pet/api/health` מחזיר `ok`.
- לפתוח את פאנל האדמין ולוודא שהזמנות ומוצרים נטענים.
- לבצע הזמנת בדיקה ולהדפיס תווית.
- להגדיר `WAREHOUSE_WHATSAPP_NUMBER` ב-SSM (אופציונלי; בלעדיו השליחה נפתחת
  עם בחירת איש קשר).
- למלא משקל למוצרים קיימים בקטלוג — השדה נוסף, הערכים ריקים.

- לאחר שהשחרור אושר כתקין, אפשר למחוק את טבלת הסנאפשוט; היא מחזיקה מידע אישי
  שאין לו עוד תפקיד:
  `drop table public.profiles_identity_snapshot;`

### אם משהו נשבר

הקוד ניתן להחזרה: `git revert` על המיזוג ודחיפה.

הסכימה לא ניתנת להחזרה — `0019` מוחקת עמודות — אבל **הנתונים כן**:
`profiles_identity_snapshot` מחזיקה את `email`, `full_name`, `phone`
ו-`birthdate` של כל פרופיל כפי שהיו רגע לפני המחיקה. נבדק: הערך היחיד
ש-`0019` זורק (כשהשתיים חלוקות) נשלף משם.
