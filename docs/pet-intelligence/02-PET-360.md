# 02 — Pet 360

Pet 360 is a **read model**, not a table. It composes canonical sources and
returns every value with its provenance. If Pet 360 ever becomes a place data is
written to, the design has failed.

```
                        ┌──────────────────┐
                        │     PET 360      │   a projection
                        │   (read model)   │   rebuilt from sources
                        └────────┬─────────┘
                                 │ composes
   ┌──────────┬──────────┬───────┼────────┬──────────┬──────────┬──────────┐
   │          │          │       │        │          │          │          │
 pets    pet_facts  pet_observ  pet_    pet_vet_  orders +  outbox_   pet_insights
identity  current    ations    documents visits    order_    events   (projection)
          per key              +extract  vaccin.   items     timeline
```

## The Pet 360 contract

One endpoint, composed server-side, every value shaped the same way:

```jsonc
{
  "pet": { "id": "…", "name": "Blue", "species": "dog", "breed": "Labrador",
           "birth_date": "2022-04-02", "birth_date_precision": "EXACT",
           "age_years": 4, "age_months": 5 },

  "derived": {
    "life_stage": { "value": "ADULT", "source": "SYSTEM_DERIVED",
                    "derived_from": ["birth_date", "species", "size_band"],
                    "rule_version": "life_stage@2026-09-01" },
    "size_band":  { "value": "LARGE", "source": "SYSTEM_DERIVED",
                    "derived_from": ["physical.weight", "breed"] }
  },

  "facts": {
    "physical.weight": {
      "value": 28.2, "unit": "kg",
      "source": "VET_DOCUMENT", "source_id": "doc_123",
      "confidence": "HIGH", "verification_status": "DOCUMENT_EXTRACTED",
      "observed_at": "2026-09-09", "effective_from": "2026-09-09",
      "effective_to": null
    },
    "health.allergy": [
      { "value": "chicken", "source": "VET_DOCUMENT", "source_id": "doc_88",
        "confidence": "HIGH", "verification_status": "USER_CONFIRMED",
        "effective_from": "2025-11-02", "effective_to": null }
    ]
  },

  "health":   { "vet_visits": [...], "vaccinations": [...] },
  "commerce": { "recent_orders": [...], "repeat_products": [...] },
  "activity": { "status": "NOT_AVAILABLE" },
  "documents":[ ... ],
  "timeline": [ ... ],
  "insights": [ ... ]
}
```

**Three properties this shape guarantees:**

1. **Nothing is a bare value.** A consumer that renders a number cannot avoid
   knowing where it came from.
2. **Derived values name their inputs and their rule version.** A life stage that
   looks wrong is debuggable, and a rule change is attributable.
3. **Absence is explicit.** `"activity": { "status": "NOT_AVAILABLE" }`, not an
   empty array that reads as "this pet does nothing".

## Two audiences, two shapes

| | Customer app | CRM / admin |
|---|---|---|
| Sees | `Blue · 4 years · 28.2 kg · Labrador · Adult` | every fact, with source, confidence and timestamp |
| Provenance | only where it earns trust — "from your vet document, 9 Sep" | always |
| Confidence | never as a number | as a level |
| Superseded facts | never | yes, with the supersession chain |
| Rule versions, `derived_from`, fact ids | never | yes |

The customer surface must not leak the model. No "confidence", no
"AI_INFERRED", no fact ids, no database words. What the owner gets is a clean
profile and, where it helps them trust a number, one line of plain language:
*"מהמסמך הווטרינרי, 9 בספטמבר"*.

`36` of the brief is the rule: **simple on the surface, structured underneath.**

## Performance

Pet 360 is a fan-out read. Two safeguards, both already precedented in this
codebase:

- **Current-fact index.** `pet_facts` gets a partial index on
  `(pet_id, namespace, key) where effective_to is null`, so "current value" is a
  single index scan and never a `max(effective_from)` sort.
- **The feed query is the model.** `listSocialFeed` composes counts, viewer
  state and poll aggregates in **one** statement with correlated subqueries and
  no N+1. Pet 360 should be built the same way, not as twelve round trips.

Caching is deliberately **not** proposed at this stage: a projection that can be
rebuilt cheaply does not need a cache, and a cache is the fastest way to
accidentally create a second source of truth.
