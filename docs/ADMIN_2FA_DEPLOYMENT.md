# פריסת אימות דו-שלבי למנהלים — מה חייב לקרות לפני המיזוג

הענף `claude/admin-2fa` הופך אימות דו-שלבי לחובה בכניסה לפאנל הניהול.
**אסור למזג ולפרוס אותו לפני שהמשימה החוסמת למטה בוצעה ואומתה.**

## המשימה החוסמת: `SECRET_ENCRYPTION_KEY` ב-SSM ובשרת

זרעי ה-TOTP נשמרים בבסיס הנתונים מוצפנים. בלי המפתח אין הצפנה ואין
פענוח, ולכן בפרודקשן `server/src/index.js` מסרב לעלות בלי המשתנה הזה.
זו התנהגות מכוונת — עדיף כשל בפריסה מאשר פאנל שאיש אינו יכול להיכנס אליו.

### למה הסדר קריטי

`deploy/aws/docker-compose.yml` קורא את הסביבה מ-`env_file: /opt/mipo/.env`,
וה-workflow של הפריסה מחריג את `.env` מה-rsync. הקובץ הזה מתעדכן **רק**
דרך `deploy/aws/sync-ssm-env.sh`.

ב-`.github/workflows/deploy-aws.yml` המיגרציות רצות **לפני**
`docker compose up -d --wait`. אם המפתח חסר בזמן הפריסה, זה מה שקורה:

1. מיגרציה `0031_admin_two_factor.sql` נכתבת לבסיס הנתונים ומצליחה.
2. הקונטיינר החדש עולה, זורק, ונכנס ללולאת restart.
3. `--wait` נכשל אחרי 60 שניות והפריסה נופלת.
4. **ה-API בפרודקשן למטה** עד שהמפתח יוכנס ותיעשה פריסה חוזרת.

לכן: המפתח נכנס ל-SSM ומשם ל-`/opt/mipo/.env` **לפני** שהקוד נפרס.
זה בטוח לעשות מראש — הקוד הישן פשוט מתעלם מהמשתנה.

### הצעדים

**1. ייצור המפתח** (מכל מקום; אין תלות בריפו):

```
echo "prod-2026:$(openssl rand -base64 32)"
```

או, מתוך הריפו על הענף הזה:

```
npm run secret:keygen --prefix server -- prod-2026
```

הפלט הוא שורה אחת: `prod-2026:` ואחריו 44 תווי base64 (32 בתים).
אין להעביר אותה בצ'אט, במייל, בווטסאפ או בכל ערוץ שנשמר.

**2. שמירה ב-SSM כ-SecureString:**

```
aws ssm put-parameter --profile mipo --region eu-central-1 --name "/mipo/prod/SECRET_ENCRYPTION_KEY" --type SecureString --value 'הערך-מהשלב-הקודם' --overwrite
```

הגרשיים הבודדים נחוצים: base64 מכיל `+` ו-`/`.

**3. אימות שהערך נשמר במלואו:**

```
aws ssm get-parameter --profile mipo --region eu-central-1 --name "/mipo/prod/SECRET_ENCRYPTION_KEY" --with-decryption --query 'Parameter.Value' --output text | wc -c
```

צריך להחזיר `55` — כלומר 10 (`prod-2026:`) + 44 + שורה חדשה.

**4. דחיפה ל-`.env` בשרת:**

```
bash deploy/aws/sync-ssm-env.sh
```

**חייב לרוץ מתוך הענף הזה.** ה-`KEYS` בסקריפט הוא רשימת היתר סגורה;
הגרסה שב-`aws-migration` תדלג על `SECRET_ENCRYPTION_KEY` בשקט ותשאיר
`.env` בלי המפתח.

**5. אימות שהקונטיינר מפענח אותו נכון** — אין לדלג על הצעד הזה:

```
ssh -i ~/.ssh/mipo-prod-key.pem ubuntu@63.183.241.110 "cd /opt/mipo && docker compose -f deploy/aws/docker-compose.yml exec -T mipo-api node -e 'const v=process.env.SECRET_ENCRYPTION_KEY||\"\"; const b=v.split(\":\").pop(); console.log(\"bytes=\"+Buffer.from(b,\"base64\").length)'"
```

צריך להדפיס `bytes=32`. כל תוצאה אחרת פירושה שמשהו נדבק לערך —
לרוב גרשיים שנכנסו ל-`.env` — והשרת יסרב לעלות עם `invalid_key_length`.
התיקון: לערוך את `/opt/mipo/.env` ולהסיר את הגרשיים סביב הערך.

**6. רק אחרי ש-`bytes=32` חזר — למזג ולפרוס.**

## אזהרה תפעולית: כל המנהלים ננעלים עד רישום

ברגע שהקוד עולה, כל מנהל קיים נדרש לרשום אפליקציית אימות בכניסה הבאה
שלו. הכניסה עצמה עובדת; הפאנל נחסם עד שהרישום הושלם. הרישום מסתיים
במסך אחד ואינו מנתק את ה-session.

יש לתאם מועד עם כל מי שמשתמש בפאנל לפני הפריסה, כדי שאיש לא יגלה את זה
באמצע עבודה.

## שחזור למנהל שאיבד גם מכשיר וגם קודי שחזור

```
npm run admin:provision --prefix server -- --email <כתובת> --role admin
```

מנקה את הרישום, את הזרע ואת קודי השחזור, ומדפיסה סיסמה זמנית חדשה.
דורש `DATABASE_URL` על השרת — אין לזה נקודת קצה ב-HTTP, בכוונה.

## שינוי נוסף ששחר צריך לדעת עליו

`POST /api/admin/bootstrap` **הוסר**. ה-`ON CONFLICT DO UPDATE` שלו איפס
סיסמה של כל מנהל והפעיל מחדש חשבון מושבת, לכל כתובת מייל, מכל מקום
ברשת, מוגן רק בכותרת `X-Admin-API-Key` סטטית אחת — כלומר מסלול עוקף
לאימות הדו-שלבי. יצירה ואיפוס עוברים מעכשיו רק דרך `admin:provision`.

אם קיים סקריפט או תיעוד פנימי שמשתמש בנקודת הקצה הזאת, יש להחליף אותו.

## חזרה לאחור

ההחזרה של הקוד לגרסה הקודמת בטוחה: מיגרציה `0031` רק מוסיפה עמודות
וטבלה, ואינה מוחקת דבר. קוד ישן פשוט מתעלם מהן. אין צורך למחוק את
המפתח מ-SSM.
